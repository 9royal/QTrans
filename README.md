# QTrans — 類 QTranslate 的桌面即時翻譯工具

在任何程式裡選取文字，按 `Ctrl+Q`，譯文就出現在滑鼠旁邊。常駐系統匣，不綁瀏覽器。

> **只是想裝起來用？** 跳過這份文件，看 [`開始使用.txt`](開始使用.txt)。
> **想分享給同事？** 看 [`分享給同事.md`](分享給同事.md)。

為了取代已停止維護的 QTranslate 而寫，操作手感刻意做得一樣，引擎換成現在還能用的：
Google（免金鑰）、DeepL、Gemini、OpenAI 相容端點、LibreTranslate。

# 第一部分：安裝與使用

## 一、安裝（約 5 分鐘）

### 步驟 1：確認有 Python

按 `Win + R`，輸入 `cmd`，按 Enter，然後輸入：

```bat
python --version
```

- 看到 `Python 3.10` 或更新 → 往下做。
- 顯示「找不到」或跳出 Microsoft Store → 先到 [python.org](https://www.python.org/downloads/) 下載安裝。
  **安裝時務必勾選最下方的「Add python.exe to PATH」**，否則後面每個指令都會失敗。

### 步驟 2：解壓縮

把 `QTrans.zip` 解壓到一個固定的位置，例如：

```
D:\QTrans\
```

不要放在桌面或「下載」資料夾 —— 之後要設定開機自動啟動，程式位置若改變設定就會失效。

### 步驟 3：安裝相依套件

在 `QTrans` 資料夾的空白處**按住 Shift + 滑鼠右鍵** → 選「在這裡開啟 PowerShell 視窗」，然後輸入：

```bat
pip install -r requirements.txt
```

會下載 PySide6（約 70MB，是介面框架），大概一兩分鐘。

### 步驟 4：確認金鑰加密功能正常

```bat
python -m qtrans.keyvault
```

應該看到：

```
平台        ：win32
加密後端    ：Windows DPAPI（綁定目前使用者帳號）
✓ DPAPI 加解密正常，金鑰會被加密儲存。
```

**這一步請務必執行。** 加密金鑰的那段程式呼叫的是 Windows 底層 API，我在 Linux 容器裡沒辦法實測，只能靠這個指令在你的電腦上驗證。如果出現 ✗，把訊息貼給我。

### 步驟 5：啟動

```bat
pythonw run.py
```

注意是 **`pythonw`**（結尾有 w），不是 `python`。`pythonw` 不會留一個黑色主控台視窗。

畫面右下角系統匣會出現一個藍色「譯」圖示，並跳出「QTrans 已啟動」的提示。**裝好了。**

> 如果用 `python run.py`（沒有 w），程式照樣能跑，但會多一個黑窗，關掉黑窗程式也會跟著結束。

### 步驟 6（選用）：做一個好按的捷徑

在桌面按右鍵 → 新增 → 捷徑，位置填入（路徑換成你自己的）：

```
pythonw "D:\QTrans\run.py"
```

命名為 QTrans。之後雙擊就能啟動。

## 二、第一次設定

在系統匣的「譯」圖示上**按右鍵 → 設定…**

### 先填 Gemini 金鑰（建議）

到 [Google AI Studio](https://aistudio.google.com/apikey) 建立一組免費的 API 金鑰，貼進
**「翻譯引擎」分頁 → Gemini → API 金鑰**。

填完按一下旁邊的**「列出可用模型」**，從清單裡挑一個 `flash` 結尾的（速度快、便宜）。
這個按鈕會用你的金鑰直接去查目前真正能用的模型 —— Google 模型改名很勤，
哪天預設值失效了，按一下重選就好，不用改程式。

然後回到**「一般」分頁**，把「預設引擎」改成 Gemini。

> **為什麼建議 Gemini 而不是用預設的 Google 免金鑰版？**
> 免金鑰版開箱可用，但它走的是非官方端點，可能限流（回 HTTP 429）。
> 而 Gemini 是語意翻譯，長句、學術文字、專有名詞的品質明顯好很多，
> 預設提示詞已經要求「繁體中文使用臺灣用語、保留換行與編號、只輸出譯文」。
> 把 Google 免金鑰版留著當備援就好 —— 彈窗左上角隨時能切換。

### 建議順手開的兩個選項

- **一般 → LLM 引擎逐字輸出**（預設已開）：長文不必等整段翻完，0.5 秒就開始跑字。
- **一般 → 開機時自動啟動 QTrans**：常駐工具開機就在才有意義。

### 金鑰存在哪裡、安不安全

金鑰經 **Windows DPAPI** 加密後才寫進 `%APPDATA%\QTrans\config.json`，長這樣：

```json
"api_key": "dpapi:v1:AQAAANCMnd8BFdERjHoAwE/Cl+sBAAAA..."
```

加密金鑰由 Windows 依你的登入帳號自動衍生，所以：

- 其他 Windows 帳號讀不到。
- 把 `config.json` 複製到別台電腦也解不開。
- 同帳號下的程式若想偷偷解密，還缺一組程式內建的 entropy（第二把鑰匙）。

**附帶的代價**：換電腦或重裝 Windows 之後，舊金鑰一定解不開。
這是 DPAPI 的設計而非故障，程式會在啟動時跳出「有金鑰無法解密，請重新輸入」，
到設定裡重新貼一次就好。

## 三、日常使用

| 熱鍵 | 功能 |
|---|---|
| **`Ctrl + Q`** | 翻譯選取的文字，彈窗出現在滑鼠旁 |
| `Ctrl + Shift + Q` | 開啟主視窗並帶入選取文字（適合長文、要編輯的時候） |
| `Ctrl + E` | 朗讀選取的文字 |
| **連按兩下 `Ctrl`** | 同「開啟主視窗」 |
| `Esc` | 關閉彈窗 |

全部可在「設定 → 熱鍵」改。

### 彈窗上能做什麼

- **左上角下拉選單**：換引擎。換了會立刻用新引擎重譯同一段文字，**比對譯文品質很方便**。
- **旁邊的下拉選單**：換目標語言，同樣立刻重譯。
- **📌**：釘選。不釘的話點到別的視窗彈窗就收起來了；要慢慢讀或複製時先釘住。
- **複製 / 朗讀 / 搜尋 / 主視窗** 四個按鈕。

### 主視窗能做什麼

- 左邊貼原文，`Ctrl+Enter` 翻譯，右邊出譯文。
- **⇄ 按鈕**：把譯文丟回左邊並對調語言，適合來回修稿。
- **右側歷史紀錄**：所有翻譯都會存下來（最多 1000 筆，可搜尋），雙擊可載回。
  整理教材術語時，同一個詞不用反覆查。
- 關閉視窗只是收回系統匣，不會結束程式。要結束請從系統匣右鍵 → 結束。

### 中英互譯的小設計

目標語言設繁體中文時，如果你選到的本來就是中文，會自動改譯成英文（備用目標語言）。
所以中翻英、英翻中都是同一個 `Ctrl+Q`，不用先切語言。可在設定中關閉。

## 四、打包成 exe（想給同事或裝到學校電腦時）

```bat
build.bat
```

產出 `dist\QTrans\QTrans.exe`，整個 `QTrans` 資料夾複製到別台電腦就能跑，**對方不必裝 Python**。

設定與歷史存在 `%APPDATA%\QTrans\`，不在程式資料夾裡，所以更新程式不會洗掉設定。

## 五、疑難排解

| 症狀 | 原因與處理 |
|---|---|
| 按 `Ctrl+Q` 沒反應 | 熱鍵被其他程式占用了。啟動時系統匣會提示哪一組失敗，到「設定 → 熱鍵」換一組（例如改成 `Ctrl+Alt+Q`）。 |
| 跳出「沒有抓到文字」 | 真的沒選到字，或該程式不給複製。先確認 `Ctrl+C` 在那個程式裡能用。 |
| 在某個程式裡完全無效 | 那個程式是用**管理員權限**開的（例如以管理員身分開的編輯器）。一般權限的程式無法對它送模擬按鍵。解法：QTrans 也以管理員身分執行。 |
| 譯文顯示 HTTP 429 | Google 免金鑰端點限流了。換成 Gemini 或 DeepL，或等幾分鐘。 |
| 「有金鑰無法解密」 | 換過電腦或重裝 Windows。到設定重新貼一次金鑰。 |
| 翻完剪貼簿變空的 | 原本複製的是圖片或檔案。程式只能還原純文字剪貼簿，這是「借用剪貼簿取字」這個做法的共同代價，QTranslate 也一樣。 |
| 朗讀沒聲音 | 檢查「設定 → 外觀與其他 → 朗讀音量」，以及系統音量。朗讀走 Google 的免金鑰端點，需要連網。 |

# 第二部分：技術說明

這部分是給你（或未來要改這個程式的人）看的，日常使用不需要讀。

## 六、三個關鍵設計決定

### 1. 熱鍵用 Windows 原生 `RegisterHotKey`，不用鍵盤監聽套件

這是整個程式最關鍵的一點。

網路上大多數自製翻譯小工具用 `keyboard` 或 `pynput` 監聽按鍵，問題是**那些套件不攔截按鍵**：
你按 `Ctrl+Q`，翻譯視窗跳出來的同時，前景程式**也收到了** `Ctrl+Q`（在很多程式裡是「結束」）。

`RegisterHotKey` 由作業系統獨佔該組合鍵，按下後**不會**再傳給前景程式，這才是 QTranslate 的做法。
代價是必須自己跑 Win32 訊息迴圈，程式碼在 `qtrans/hotkeys.py`。

「連按兩下 Ctrl」沒辦法用 `RegisterHotKey`（它不接受單純的修飾鍵），所以另外掛一個
`WH_KEYBOARD_LL` 低階鍵盤掛鉤。這個掛鉤**不攔截**任何按鍵，每個事件都原封不動往下傳
—— 單按 Ctrl 本來就沒有作用，不攔也沒差。掛鉤回呼裡只做狀態判斷，絕不做耗時工作，
否則 Windows 會因逾時把掛鉤整個拆掉。

### 2. 取字用「哨兵字串 + 輪詢」，不用固定延遲

Windows 沒有「讀取別的程式裡選取文字」的通用 API，只能借用剪貼簿：
備份 → 送 `Ctrl+C` → 讀回來 → 還原。

關鍵在「送出之後要等多久才讀」。常見做法是固定 `sleep(100ms)`，但那樣**無法分辨三種情況**：

| 實際狀況 | 固定延遲的結果 |
|---|---|
| 程式回應慢（Office、Acrobat、遠端桌面） | 讀到**舊的**剪貼簿內容，拿去翻譯 |
| 使用者根本沒選取文字 | 讀到**舊的**剪貼簿內容，拿去翻譯 |
| 正常選取 | 正確，但白等 100ms |

前兩種你會看到一段跟選取內容完全無關的譯文，而且程式不會報錯。調高延遲治不了
—— 只會讓每次都變慢，遇到更慢的程式照樣失敗。

本程式的做法是先把剪貼簿塞一個不可能出現的哨兵字串，然後輪詢直到內容改變：
快的程式 30ms 就回來，慢的最多等 700ms，而且**一直沒變就確定是沒選取文字**，
可以明確提示而不是亂翻一段。（`qtrans/capture.py`）

### 3. 送 `Ctrl+C` 前必須先鬆開實體修飾鍵

熱鍵觸發的瞬間，使用者**手指還在 Ctrl 上**。若直接送 `Ctrl+C`：

- 熱鍵若含 Shift（例如 `Ctrl+Shift+Q`），送出的實際是 **`Ctrl+Shift+C`**，
  在 Chrome 是開啟檢視元素，在很多編輯器是別的指令。
- 程式主動 Release 了 Ctrl，但實體按鍵還按著，作業系統的修飾鍵狀態會**失去同步**，
  之後容易出現 Ctrl 卡住的詭異現象。

所以送出前要把所有修飾鍵（Ctrl / Shift / Alt / Win 的左右鍵全部）主動送 keyup
—— `capture.py` 的 `_release_modifiers()`。

### 其他
- **擷取與翻譯都在背景執行緒**：剪貼簿輪詢最多 0.7 秒、網路請求可能更久，
  都丟到 `QThreadPool`，主執行緒只管畫面，所以彈窗能立刻顯示「翻譯中…」。
- **彈窗定位會做螢幕邊界修正**：在螢幕右緣或下緣選字時，彈窗會翻到游標另一側，
  不會跑出畫面外（`show_at_cursor()`）。

## 七、金鑰加密（`keyvault.py`）

用 `CryptProtectData` / `CryptUnprotectData`，透過 ctypes 直接呼叫，不需要 pywin32。

幾個實作上的要點：

- **自訂 entropy**：加解密都帶一組程式內建的鹽值當第二把鑰匙。
  同帳號下的其他程式若盲目呼叫 `CryptUnprotectData` 會解不開。
  改動 `_ENTROPY` 會讓所有既有密文失效。
- **`dpapi:v1:` 前綴**：用來分辨「已加密」與「舊版留下的明文」。
  舊設定檔第一次讀進來照舊可用，存檔時自動變成密文 —— 無痛遷移，不用手動處理。
- **不重複加密**：已是密文的值不會再被加密一次（存兩次就解不開了）。有測試守住。
- **`LocalFree`**：Windows 配置的緩衝區必須手動釋放，否則每次加解密都洩漏記憶體。
- **`save()` 不污染呼叫端的 dict**：記憶體中的設定仍是明文（要拿去發請求），
  只有落地的那份是密文。有測試守住。
- **解密失敗必須優雅降級**：清空欄位、記錄原因、啟動時提示重新輸入，不可以當掉。

## 八、串流輸出（SSE）

Gemini 走 `:streamGenerateContent?alt=sse`，OpenAI 相容端點走 `stream: true`，
都逐行解析 `data:` 開頭的 SSE 訊息。

- **取消機制**：每讀一行都檢查取消旗標。連續選取多段文字時，舊的串流會在下一行就停掉
  —— 否則兩段譯文會在同一個視窗裡交錯輸出，而且白燒 API 額度。
- **最終覆蓋**：串流時無法預知模型會不會包 markdown 圍籬，所以逐字顯示只當預覽，
  結束時用清理過的完整譯文覆蓋一次（通常完全相同，不會閃動）。
- **送出前就決定目標語言**：LLM 不回報來源語言。原本是等譯文回來才發現「原文本來就是
  目標語言」然後重譯，但串流模式下那會變成畫面上的字跑完又全部重跑。
  改成先用本地判斷（中/英/日/韓）把語言定好，一次就送對（`app.py` 的 `_resolve_target`）。
- **高度不變就不重排**：串流每收到一段都會呼叫 `_resize_to_content()`，
  加了高度比對的早退，避免每個 token 都重算版面。

## 九、延遲載入

建立 `requests.Session` 會載入 TLS 憑證庫，約數十到數百毫秒。常駐工具若在開機時就做，
會被 Windows 標記為「啟動影響：高」。所以推遲到第一次真的要翻譯時才建立，
之後重複使用同一個連線池，順便省掉每次重新 TLS 握手（`engines.py` 的 `http()`）。

## 十、程式結構

```

  hotkeys.py          全域熱鍵（RegisterHotKey + 低階掛鉤）
  capture.py          擷取選取文字（哨兵輪詢 + 鬆開修飾鍵）
  engines.py          五個翻譯引擎、延遲連線池、SSE 串流
  worker.py           背景翻譯任務與取消機制
  history.py          SQLite 歷史紀錄
  tts.py              朗讀
  icons.py            程式內繪製圖示（不需外部圖檔）
  startup.py          開機自動啟動（登錄檔 Run 鍵）
  ui_popup.py         滑鼠旁彈出視窗
  ui_main.py          主視窗
  ui_settings.py      設定視窗
  app.py              把以上全部接起來
tests/
  test_qtrans.py      66 項測試
  qt_stub.py          PySide6 替身，讓測試能在沒有 Qt 的環境跑
```

### 想自己加一個引擎

在 `engines.py` 加一個類別就好，引擎下拉選單是自動從註冊表產生的：

```python
@register
class MyEngine(Engine):
    id = "my_engine"
    label = "我的引擎"
    needs_key = True

    def translate(self, text, src, tgt):
        data = self._post_json("https://example.com/api",
                               json={"q": text, "to": tgt})
        return Result(text=data["result"], engine=self.label,
                      source_text=text, target_lang=tgt)
```

然後在 `config.py` 的 `DEFAULTS["engines"]` 加設定欄位、
在 `ui_settings.py` 的「翻譯引擎」分頁加輸入框。
若金鑰需要加密，記得把欄位路徑加進 `config.py` 的 `SECRET_PATHS`。

## 十一、已驗證與未驗證

**66 項測試涵蓋：**

- 全部 14 個模組可正常匯入
- 金鑰：加解密往返、不重複加密、舊版明文遷移、解密失敗降級、Base64 損毀、非 Windows 誠實標示
- 設定：巢狀合併、損毀回退、**金鑰絕不明文落地**、`save()` 不污染呼叫端 dict
- 五個引擎的回應解析（Google 詞典／拼音、長文多段接合、Gemini 圍籬清除與安全攔截、DeepL 的 `ZH-HANT` 對應）
- SSE 串流：逐字輸出、`[DONE]` 處理、圍籬清除、**取消時立即停止並關閉連線**、HTTP 錯誤關閉連線、非 LLM 引擎退回一次性
- 送出前決定目標語言的五種情況
- 長文切塊：多行與超長單行中文都不掉字
- 連線池延遲建立與重用
- 熱鍵字串／虛擬鍵碼對應，預設三組確實可註冊
- 歷史紀錄的新增、上限、搜尋、清空；朗讀切塊

**未驗證（需要真的 Windows 桌面環境）：**

1. **DPAPI 的 ctypes 呼叫** —— 加解密邏輯有測試（用假後端），但真正的 Windows API
   呼叫只能在你的電腦上驗。**請跑 `python -m qtrans.keyvault`。**
2. **Win32 熱鍵註冊與低階掛鉤** —— 需要實機按下去才算。
3. **Qt 介面的實際繪製**。
4. **真實 API 的串流格式** —— SSE 解析是照目前的 API 格式寫的並有測試覆蓋，
   但真實回應偶爾會有額外欄位。

## 十二、要不要改用 Tauri 重寫

如果你後來覺得這工具值得投資更多，Tauri + Rust 的版本有一個明確的好處：
**安裝檔約 5～10MB，而 PyInstaller 打包是 80～150MB**。要裝到學校電腦或分享給同事時，差距有感。

但有兩件常見的誤解值得先講清楚：

- **記憶體不是理由。** Tauri 常被說「不到 30MB」，但那是二進位檔大小，不是 RAM。
  WebView2 是多進程架構，一個開著視窗的小工具實際駐留約 60～120MB，
  和這個 PySide6 版（60～90MB）差不多。
- **取字和熱鍵不會因為換 Rust 就變好。** 上面第六節那三個設計決定是平台層面的問題，
  跟語言無關。用 Tauri 重寫時一樣要處理哨兵輪詢、鬆開修飾鍵、螢幕邊界修正，
  否則會比這個版本難用。

真正的 Tauri 代價是迭代速度：每次改動都要重新編譯（首次 1～3 分鐘），
加上要裝 Rust + MSVC 建構工具（好幾 GB）。

**建議：先用這個版本一兩週。** 如果你確實天天按 `Ctrl+Q`，而且需要散佈給別人，
那時再重寫就是划算的投資；如果一週只用幾次，省下來的時間做別的事更值得。
